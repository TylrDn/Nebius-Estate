# Security

What protects credentials, state, exposure and workloads in every recipe, what is enforced by a check,
and where the repository knowingly falls short.

## State and secret threat model

Trace where credentials appear: shell, config, plan, state, logs, CI.

| Location | What can leak | Mitigation |
|---|---|---|
| Terraform state | sensitive attribute values | versioned bucket per stage, locking, bucket-scoped identity ([ADR-0005](decisions/0005-terraform-state-boundaries.md)) |
| Saved plans | the same as state, plus variable values | git-ignored; the pipeline never uploads them and never publishes their text: the job summary holds the resource-change digest, counts and addresses only (`make plan-summary`), and the apply job re-plans and refuses on a mismatch ([change management](change-management.md#the-path)) |
| CI logs | echoed variables, plan diffs | GitHub masks secrets; the pipeline's plans run with `PLAN_LOG=false`, so no diff (attribute values) reaches the log; locally `make show-plan` relies on Terraform's redaction of sensitive values. No token is passed in a process's argv: CI and recipe scripts send bearer tokens as headers read from a file descriptor or stdin, and `docker -e NAME` by name (`tests/scripts`) |
| Local shell | exported tokens | short-lived user token (~12 h); `iam_token` is an ephemeral variable, never in plans or state |

Prefer Terraform write-only arguments and the Nebius `sensitive` object where the resource schema
supports them, and use a non-secret revision indicator for `sensitive.version`, never the raw secret.

## Demo defaults not to copy into production

From the upstream recipes (`k8s-training`, and the `k8s-inference` recipe that upstream has since removed):

- Grafana `admin/admin` credentials: replace them, and keep dashboards off the public internet.
- hostPath-backed ReadWriteMany PVs: assess isolation, mount consistency, capacity and recovery.
- Promtail: confirm the currently maintained log collector and chart versions.
- Cluster ID read from a local `terraform.tfstate`: use an explicit Terraform output.
- Sample CPU and GPU node counts: examples, not sizing guidance.

## Security acceptance checklist

Each item names where it is enforced or documented, and what is still only a claim.

| Item | Enforced / documented by | Status |
|---|---|---|
| No credentials committed | `.gitignore` (state, plans, `*.tfvars` except the committed per-stage sizing files and Soperator profiles, kubeconfigs, `backend.hcl`, `results/*.state`); gitleaks over the committed history in CI (`make scan`) | enforced |
| State access is scoped | versioned bucket with `prevent_destroy`. Two state identities per CI stage, each a project group + bucket-scoped access permit: the read-write one (`storage.object-editor`; local runs and the apply job) and, with `ci = true`, a read-only one (`storage.object-viewer`; the plan job, foundation output `ci_plan_state_identities`). `scripts/bootstrap-backend.sh` stops if the API refuses the bucket scope (`NIP_STATE_PERMIT_SCOPE=project` is an explicit wider opt-in). Locally the state key lasts one day. **In CI the state keys are static GitHub Environment secrets**, read-only in `<stage>-plan` and read-write in `<stage>`, each with an expiry set at creation and a rotation procedure ([`runbooks/credential-rotation.md`](../runbooks/credential-rotation.md#rotating-the-ci-state-access-keys)); minting a key per job needs `admin` (access keys: create is admin-only in [roles](https://docs.nebius.com/iam/authorization/roles#general-roles)), which no CI identity holds. **The plan job takes no state lock**: a read-only key cannot write the lock file, so it plans with `-lock=false`, and a run outside this workflow can race its read; the apply job re-plans under the lock with the read-write key and refuses unless the digest matches ([change management](change-management.md#the-path)). Which key sits in which environment is configuration in GitHub, not code: a read-write key placed in `<stage>-plan` would not be detected | enforced locally and by the foundation's grants; CI keys long-lived by design; the plan job's lock-free read is a stated gap |
| Plan and apply identities | two CI service accounts per stage (`ci = true` in the foundation), each through a group in that stage's project only (`modules/foundation/ci-service-account`): `editor` for the apply job (`<stage>` environment) and `viewer` for the plan job (`<stage>-plan`). With the read-only state key above, a plan from any ref its environment admits can read the stage and its state but change neither. Their authorized keys are registered with the CLI, with an expiry ([credentials](credentials.md#ci-service-account-keys)). In a job the private key lives only until the token is minted: `scripts/ci-token.sh` reads it by path into a throwaway CLI config and deletes the config, the action deletes the key file, and later steps hold only the short-lived token (`TF_VAR_iam_token`). On the federated path (R13) the subjects pin GitHub's immutable repository and owner ids by default (`subject_claims = "ids"`). Environment rules (ref restrictions, required reviewers on prod) and the digest check add to that; `sandbox-plan` and `sandbox` admit any ref by design ([change management](change-management.md#enabling-the-pipeline), step 4) | enforced by the foundation's grants and the scripts; ref rules are GitHub configuration |
| Identity and access model documented | IAM token or service-account key for Terraform ([`terraform/README.md`](../terraform/README.md#authentication)); team namespaces with namespace-scoped RBAC (`recipes/team-platform/namespaces`); Soperator identity conflict ([`soperator-compatibility.md`](soperator-compatibility.md)) | documented |
| Public exposure justified and minimised | vLLM and Grafana reachable by port-forward only (no public Service or Ingress); control-plane endpoint per stage policy (`public_endpoint`): prod private, and a request for `public_endpoint = true` in prod is refused by the stage policy (a request may tighten the policy, never loosen it); staging public only behind `allowed_cidrs`; sandbox may be public without an allowlist (TTL-bound). Node public IPs off; security groups per node group; R7 bastion and R10 public address only from `allowed_cidrs`. Allowlist entries: RFC 5737 documentation ranges refused, and entries wider than /8 (`0.0.0.0/0`, the two `/1` halves) refused wherever an allowlist is required (staging, prod, a public bastion in any stage) by the `stage-policy` module, always by the R7 and R10 variable validations, and in committed sizing files by conftest (`policy/allowlists.rego`). Node SSH: the pipeline passes `NIP_SSH_PUBLIC_KEY` to R10 only, and the node-group cloud-init renders a key as one escaped string, so it cannot add users or sudo rules. Soperator login-node public IP justified in [ADR-0008](decisions/0008-slurm-scheduler-and-soperator.md) | enforced (plan-time stage policy, variable validations, `conftest`) |
| Spend caps cover every node group | the stage GPU caps (`max_gpu_nodes`) count the GPU group; the CPU group of R1/R3 is refused a GPU platform or preset (`cpu_platform` must be `cpu-*`, `cpu_preset` not `<n>gpu-*`) and capped at 16 nodes by the stacks' variable validations and, in committed sizing files, by conftest (`policy/sizing.rego`); `modules/node-group` refuses an `<n>gpu-*` preset on a non-GPU platform. Sandbox resources must carry a `nip-ttl-expires` in the future and at most 7 days ahead of the plan (`modules/stage-policy`) | enforced (variable validations, stage policy, `conftest`) |
| Namespace and network isolation | PSS labels on every namespace. `inference`: default deny both ways, with DNS, same-namespace and o11y ingress on 8000, and 443 egress for the first model download and for the load generator's tokenizer download, the remaining wide rules (`workloads/inference/base/networkpolicy.yaml`). Job and team namespaces (`training`, `nccl-test`, `data`, team namespaces): **ingress-only** isolation (same namespace + o11y) from `workloads/components/ingress-isolation`; egress stays open because the Kubeflow MPIJob launcher reaches workers through the API server, which a NetworkPolicy cannot select reliably. Soperator namespaces: none, because the upstream recipe owns them | partial: inference isolated both ways; jobs ingress only; Soperator open |
| Workload hardening | read-only root FS, dropped capabilities, no privilege escalation and `RuntimeDefault` seccomp on the inference and DDP pods. **vLLM runs as root on purpose:** its model cache is on the shared filesystem through `csi-mounted-fs-path`, whose docs say nothing about `fsGroup`, so a non-root UID may not be able to write it; the controls above plus the NetworkPolicy compensate. **NCCL exception:** `nccl-test` enforces the `privileged` PSS level and every MPIJob container runs `privileged: true` with `IPC_LOCK` for RDMA, as in the Nebius NCCL doc, so run it only on a dedicated cluster. Trivy config scan in CI with path-scoped exceptions (`.trivyignore.yaml`) | enforced, with the two stated exceptions |
| Image and tool provenance | every container image (tag and digest), the one third-party GitHub Action (by commit SHA) and every toolbox tool (with sha256) must match `platform/versions.yaml`; `make pins` (`scripts/pins.py check`) fails on drift and runs in `make ci`. Fetched source is pinned by commit, not by a movable tag: the Soperator recipe (`scripts/fetch-soperator.sh` refuses a checkout whose commit differs from `upstream.nebius-solutions-library.ref`), the Kubeflow Training Operator manifests (`?ref=<commit>`), and Kueue's release manifest by sha256. Weekly upstream drift job (`.github/workflows/version-refresh.yml`); owner per layer in [architecture](architecture.md#ownership-map) | enforced |
| Dashboards use non-default credentials and controlled access | Grafana admin password from a SecretStash secret (`grafana_admin_secret_id`, write-only) or, without one, generated by Terraform (`modules/o11y`) with the output marked sensitive; no public exposure | enforced |
| Backup and recovery demonstrated where persistence matters | state: bucket versioning, 90-day non-current retention, `prevent_destroy`; prod filesystems and jails `forbid_deletion`, Soperator backups on; R8 checkpoint bucket versioned; [`dr.md`](dr.md), [`runbooks/backup-restore.md`](../runbooks/backup-restore.md), rollback drill in [`runbooks/rollback.md`](../runbooks/rollback.md). **Not yet demonstrated on a real cluster** | pending first deploy |
| Audit trail of control-plane access | Two separate trails. Nebius Audit Logs (preview) record control-plane events tenant-wide for IAM, Virtual Networks, Managed Kubernetes, Object Storage, KMS, SecretStash and more ([services](https://docs.nebius.com/audit-logs/services)); reading them needs `admin` or `auditlogs.audit-event-viewer` ([roles](https://docs.nebius.com/iam/authorization/roles#audit-logs)); an export is one-time per time range to a bucket in the same region and needs `storage.uploader` on it ([export](https://docs.nebius.com/audit-logs/events/export#how-to-export-events)). Separately, the stage policy's `audit_logs` (staging, prod) turns on Managed Kubernetes cluster audit logs. Keys expire (1-day local state key, dated CI keys) | MK8s audit logs enforced by stage policy; Audit Logs always on, export not automated |
| Secrets never in state where avoidable | `iam_token` ephemeral in every live root; the Grafana admin password and the R8 transfer keys come from SecretStash secrets (`grafana_admin_secret_id`, `transfer_secret_id`): they are read before the plan that is applied into ephemeral variables that feed only write-only arguments, so plans and state hold the secret and version ids, never the values. Only the apply identity may read the payloads (`mysterybox.payload-viewer` per secret, foundation `ci_secret_ids`); a plan that is only reviewed does not need them ([credentials](credentials.md#secretstash)). Fallbacks: without `grafana_admin_secret_id` the password is a state-held `random_password` (sensitive output); without `transfer_secret_id` the keys are typed into `TF_VAR_transfer_*` (still write-only). Both secrets also live in the cluster or the transfer service once applied. CI keys live only in GitHub Environment secrets | enforced when the SecretStash ids are set; the Grafana fallback keeps its password in state |

## Accepted scanner exceptions

`.trivyignore.yaml` lists every Trivy finding the repository accepts, each scoped to a file path with a
one-line justification. Review it in every PR that touches Kubernetes manifests.
