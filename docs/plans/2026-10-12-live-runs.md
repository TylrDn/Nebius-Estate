**Cancelling a TTL job.** [`scripts/ttl-teardown.sh`](../../scripts/ttl-teardown.sh) never stops an
earlier job: each `CONFIRM=yes` call starts a new background job and overwrites the root's
`.terraform/ttl-teardown.pid` with the new pid, so a job that is still sleeping loses its only handle and
later runs `make destroy-plan` and `make destroy CONFIRM=yes` against whatever the root holds by then. So
in every shell that arms or cancels a job, define (bash or zsh)
`ttl_cancel() { local f="terraform/live/sandbox/$1/.terraform/ttl-teardown.pid" p; [[ -f "$f" ]] || return 0; p="$(cat "$f")"; ps -p "$p" -o command= | grep -q ttl-teardown || return 0; kill "$p"; sleep 1; ! ps -p "$p" >/dev/null || { echo "TTL job $p for $1 still running" >&2; return 1; }; }`
(the job's command line carries `ttl-teardown`, so a stale pid reused by another process is left alone;
the pid is the job's own shell, checked offline: killing it stops the job). **Rule:** run
`ttl_cancel <stack>` before every `make ttl-teardown … CONFIRM=yes` (Z5 step 3, run 2 steps 2a–2d, run 3
step 3) and after every teardown of a root; it must return 0.
