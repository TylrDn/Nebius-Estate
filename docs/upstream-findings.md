# Upstream findings register

Gaps between the upstream Nebius solution library (`nebius-solutions-library`), the Nebius docs
and the behaviour observed in prior runs of the upstream recipes (2026-10-07/08, uk-south1; see
[`docs/evidence/`](evidence/README.md)), and how this repository handles each one. The IDs are
stable: code comments and tests cite them (`R3-8`, `R4-1`, …).

- **Upstream baseline:** [`nebius-solutions-library`](https://github.com/nebius/nebius-solutions-library)
  tag `soperator-v4.1.13-2`, sha `d1c15ca` (pinned in [`platform/versions.yaml`](../platform/versions.yaml));
  R7 and R8 also cite `main` at `fba7148` (2026-10-09) for directories that tag does not change. Docs pages
  were read on 2026-10-09 and 2026-10-11.
- **Areas:** R1 inference / Managed Kubernetes, R2 Terraform lifecycle, R3 training and NCCL,
  R4 Soperator, R6 serverless comparison, R7 network perimeter, R11 Token Factory, and the
  [2026-10-11 runs of this repository](#2026-10-11-findings-from-this-repositorys-own-runs) (R1, R2,
  R9, R14). R5 (team namespaces + SkyPilot) and R8 (data plane) have no findings yet.
- **Severity:** BLOCKER = fails on apply or at runtime; WRONG = incorrect default or claim;
  GAP = missing safeguard; NICE = polish or "verify this".
