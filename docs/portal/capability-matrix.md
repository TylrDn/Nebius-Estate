# Nebius Estate — capability matrix

The sources below were checked on 2026-10-10 and the calls were exercised on a live account on
2026-10-11 with a read-only service account holding a `viewer` permit on each listed project, and
then with a tenant-level read grant added for the tenant reads (tenant `viewer` + `security-auditor`
in this setup; evidence for each call is cited in its row):
- docs.nebius.com, including the REST API, gRPC endpoints, authentication, billing export and FOCUS
  field pages
- github.com/nebius/api at commit 97201c9 (2026-10-07)
- the public `https://api.nebius.cloud/openapi.json` (list keys and status enums are extracted into
  `plugins/nebius-estate-backend/src/inventory/apiContracts.ts` for drift detection)

The same data drives the capability matrix on **Integrations & Coverage** (`CAPABILITY_MATRIX` in
`portal/packages/nebius-domain/src/coverage.ts`). Next to it, the page shows what every call does for
*this* deployment right now: state, items, latency, last success, health over 24 h, and what to grant
when a call is refused (`yarn verify:live` prints the same table).

**Test status:**
- **live-verified:** the call answered on a real account (2026-10-11): project-level `viewer`, plus the
  tenant roles above for tenant reads and contract prices.
- **contract-tested:** unit tests against the documented request and response shapes, with mocked HTTP.
- **not-implemented:** no client; the fallback column says where to look instead.

## Authentication (documented)

- **REST:** `Authorization: Bearer <IAM access token>` against `https://api.nebius.cloud`. Errors come
  back as `{code, message}` with gRPC status codes.
- **Service account:**
  1. Sign an RS256 JWT: `kid` = authorized key id, `iss` = `sub` = service account id, expiry 5 minutes.
  2. `POST https://sts.nebius.com/oauth2/token/exchange` with the token-exchange grant (HTTP STS,
     documented under docs.nebius.com/iam/wif; the gRPC equivalent is `TokenExchangeService/Exchange`
     at `tokens.iam.api.nebius.cloud:443`).
  3. The response returns `access_token` with `expires_in` 43200 (12 h).
- **Least privilege:** a custom group with one `viewer` access permit per listed project, not the
  tenant-wide default `viewers` group and never `editors` ([setup](nebius-setup.md#read-only-nebius-identity)).
  Tenant-level reads (capacity block groups, capacity advice, listing the tenant's projects) are
  refused with project-level permits ([evidence](../evidence/2026-10-11-portal-live-read-only.md#tenant-level-reads-refused-as-expected)).
  With a tenant-level read grant they answered on 2026-10-11: block groups and the project list with
  the portal identity ([evidence](../evidence/2026-10-11-portal-ai-services.md)), advice and contract
  prices in the [pricing run](../evidence/2026-10-11-solutions-pricing.md). The setup grants tenant
  `viewer` + `security-auditor`; the minimum role is not established. Contract prices additionally need
  `resource.billinggroup.get` on the billing group.
- **TypeScript SDK:** `@nebius/js-sdk` exists (v0.2.9) and handles JWT exchange and token refresh. The
  portal uses plain `fetch` against the documented REST paths to avoid a new dependency; switching is a
  contained change in `inventory/nebius.ts`.
